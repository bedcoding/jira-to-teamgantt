# Jira to TeamGantt

Jira 이슈와 TeamGantt 작업을 한 곳에서 비교해 누락을 찾고, TeamGantt에 빠진 작업을 한 번에 등록하는 Chrome 확장 프로그램입니다.
내가 맡은 Jira 이슈를 해결한 달의 월별 에픽 아래로 한 번에 넣는 기능도 있습니다.

## 기능

- **Jira 수집**: JQL 조건에 맞는 이슈를 전량 수집. 키, 제목, 상태, 담당자, 보고자, 우선순위, 해결, 생성/업데이트 시각, 마감일, 레이블을 저장
- **TeamGantt 수집**: 열어둔 TeamGantt 탭의 인증 정보로 프로젝트 작업을 가져옴. 본인 작업만 필터링 가능. TeamGantt에서 지운 작업은 재수집 시 로컬에서도 정리됨
- **비교**: 두 출처를 Jira 키 기준으로 매칭해 `매칭` / `Jira만` / `TeamGantt 고아(키 있음/없음)` 로 분류
- **그룹에 일괄 등록**: TeamGantt에만 없는 작업을 체크해 원하는 그룹에 한 번에 생성(+담당자 자동 할당). 이미 등록한 항목은 중복 생성되지 않음
- **수동 동기화**: 단축키(`Cmd+Shift+X` / `Ctrl+Shift+X`)로 TeamGantt 활성 입력창에 한 건씩 주입하는 기존 방식도 그대로 제공
- **추출**: 선택한 기간의 항목을 `[KEY] 제목` 형식 텍스트로 모아 복사
- **월별 에픽 연결**: 내 이슈를 해결한 달의 에픽(예: `[팀] 26.09 TASKS`) 아래로 한 번에 넣고, 이미 다른 에픽에 있는 이슈는 따로 보여 주어 직접 체크한 것만 옮김
- **변경 기록**: 에픽에 넣거나 옮긴 기록을 남겨 두고 한 건, 에픽 단위, 묶음 전체로 언제든 취소하며, 넣은 것과 취소한 것을 에픽별 보고용 글로 띄워 복사
- **백업/복원**: 모든 데이터·설정을 JSON 파일로 저장하고 미리보기 후 복원

## 설치

1. 이 저장소를 clone 하거나 ZIP 다운로드 후 압축 해제
2. Chrome 주소창에 `chrome://extensions` 입력
3. 우측 상단 **개발자 모드** 켜기
4. **압축해제된 확장 프로그램을 로드합니다** 클릭
5. `jira-to-teamgantt` 폴더 선택

툴바 아이콘을 누르면 **사이드패널**이 열립니다.

> 코드를 수정한 뒤 반영하는 방법은 파일 종류마다 다릅니다.
> `popup/`·`lib/` → 사이드패널을 닫았다 열기 / `content/`·`background/`·`manifest.json` → `chrome://extensions` 에서 ↻ 새로고침 (콘텐트 스크립트는 대상 탭도 F5)

## 탭별 사용법

### 지라

1. **경로**: 본인 Atlassian 도메인 (예: `mycompany.atlassian.net`)
2. **기간**: 단위 토글(일/주/월/분기/년) 선택 후 `‹ 이전 / 이번 / 다음 ›`으로 이동. JQL의 `updated >= ... AND updated < ...` 가 함께 갱신됨
3. **JQL**: 기본값은 `assignee = currentUser() AND updated >= "..." AND updated < "..." order by updated DESC`. 직접 수정 가능

수집 버튼은 세 가지입니다.

| 버튼 | 방식 | 비고 |
|---|---|---|
| **REST 직통** | Jira REST API(`POST /rest/api/3/search/jql`)를 쿠키 세션으로 직접 호출 | 주력. 전량 수집. 아무 Jira 탭이나 열려 있으면 됨 |
| API 가로채기 | 페이지가 보낸 GraphQL 응답을 가로채 수집 | 안 잡히면 `[검색]`을 다시 실행 |
| DOM 추출 | 화면에 보이는 이슈 행을 직접 읽음 | 가상 스크롤 때문에 화면 밖 행은 빠짐 |

`REST 직통`은 `nextPageToken`을 따라가며 끝까지 받습니다. 스낵바에 `N페이지 M건 수신`이 표시되고, 상한에 걸리거나 중간에 실패해 전량이 아니면 사유를 빨간색으로 알립니다.

### 간트

1. **프로젝트** / **사용자**: ⚙️ 버튼 → `API 자동` 탭 → `[API 추출]`. TeamGantt 탭만 열려 있으면 목록을 알아서 가져옵니다 (JSON 복붙은 이제 불필요하며, 필요하면 `JSON 붙여넣기` / `1줄 추가` 탭도 남아 있습니다)
2. 본인 ID를 설정하면 본인이 담당자인 작업만 추려 저장합니다

수집 버튼은 세 가지입니다.

| 버튼 | 방식 | 비고 |
|---|---|---|
| **API 직통** | 열어둔 TG 탭의 토큰으로 `children` API를 직접 호출 | 주력. 새로고침·캐시 대기 불필요. **응답에 없는 작업은 로컬에서 정리** |
| API 가로채기 | 페이지가 보낸 API 응답을 가로채 수집 | 안 잡히면 페이지 새로고침 |
| DOM 추출 | 화면에 보이는 작업 행을 직접 읽음 | 화면 밖 행은 날짜가 빠짐 |

`API 직통`의 정리(prune)는 **로컬 저장소만** 대상입니다. TeamGantt의 데이터는 건드리지 않습니다. 0건이 수집되면 정리를 건너뛰고, 다른 프로젝트에서 수집한 작업도 건드리지 않습니다.

### 비교

상단 검색·날짜 기준·필터 칩으로 목록을 좁힌 뒤, 하위 탭 두 가지 중 하나로 작업합니다.

#### 그룹에 일괄 등록 (기본)

1. 비교 탭에 들어가면 그룹 목록이 자동으로 채워집니다 (TeamGantt 탭이 열려 있을 때). 수동으로 받으려면 `[그룹 불러오기]`
2. 표 왼쪽 체크박스로 등록할 항목 선택
   - **드래그**로 여러 건 한 번에 선택
   - **Shift+클릭**으로 범위 지정
   - 헤더 체크박스로 현재 필터에 보이는 것 전체 선택
3. 넣을 그룹 선택. 자주 쓰는 그룹은 **☆ 즐겨찾기**로 맨 위에 고정
4. `[선택 N건 등록]` → 확인창에서 건수·그룹·처음 5건(날짜 포함)을 확인하고 진행

등록되는 작업은 이름 `[KEY] 요약`, **시작일 = 종료일 = Jira 업데이트일**, 완료 상태면 진행률 100입니다.

이미 처리한 항목은 체크가 잠깁니다. 판정 근거는 셋입니다 — 단축키로 넣은 것 / API로 만든 것 / 직접 넣고 `✓` 표시한 것. 잘못 등록했다면 `✓ 등록 완료` 옆 `×`로 이력을 풀어 다시 넣을 수 있습니다.

#### 수동 동기화

1. TeamGantt 프로젝트 페이지의 새 작업 입력창에 커서를 둠
2. `[동기화 시작]` 후 단축키 → 다음 미매칭 항목이 `[KEY] 제목` 형식으로 주입됨
3. Enter로 확정 (날짜·담당자 보정은 평소처럼)
4. 다시 단축키 → 직전 항목은 큐에서 빠지고 다음 항목이 주입됨

#### 기타

- ⚙️ 버튼은 **키 추출 규칙**(정규식) 편집. TeamGantt 작업 제목에서 Jira 키를 뽑는 규칙입니다
- 키 셀 클릭 → Jira 이슈 새 탭, 제목 셀 클릭 → 클립보드 복사

### 추출

1. **소스**: Jira / TeamGantt 중 선택
2. **기간**: 지라 탭과 동일한 단위 토글 + 이전/이번/다음
3. 결과가 텍스트 영역에 쌓이면 **복사** 버튼으로 클립보드에

### 에픽

내가 맡은 이슈를 해결한 달의 월별 에픽(예: `[팀] 26.09 TASKS`) 아래로 한 번에 넣습니다.
탭 위쪽에서 **에픽에 연결**과 **변경 기록** 두 화면을 오갑니다.

#### 에픽에 연결

1. **에픽**: 월별 에픽 후보를 찾는 JQL입니다.
   기본값은 제목에 `TASKS`가 들어간 에픽이니, 팀의 에픽 이름에 맞게 고쳐 쓰세요
2. **대상**: 연결할 이슈를 고르는 JQL입니다.
   기본값은 올해 해결한 이슈와 아직 해결하지 않은 이슈입니다
3. `[불러오기]` 후 **월별 에픽**에서 한 달의 에픽을 고릅니다.
   제목 형식이 같은 에픽으로 나머지 달이 채워집니다.
   다른 팀의 월별 에픽이 검색에 섞여 들어와도 형식이 달라서 고르지 않습니다.
   줄마다 있는 `[열기]`로 고른 에픽을 Jira에서 바로 열어 볼 수 있습니다
4. 아래 세 영역을 확인하고 영역별 버튼으로 실행합니다

이슈를 넣을 달은 **해결일** 기준입니다.
해결하지 않은 이슈는 이번 달로 잡힙니다.
어떤 달을 넣지 않으려면 그 달에서 `(이 달은 연결 안 함)`을 고르세요.

| 영역 | 들어가는 이슈 | 기본 체크 | 실행 버튼 |
|---|---|---|---|
| 상위 없는 이슈 | 어느 에픽에도 속하지 않은 이슈 (달별로 묶음) | 전부 체크 | `[체크한 N건 연결]` |
| 다른 에픽에 있는 이슈 | 이미 다른 에픽 아래에 있는 이슈 (원래 에픽별로 묶음) | 체크 안 함 | `[체크한 N건 옮기기]` |
| 건드리지 않는 이슈 | 이미 그 달 에픽에 있음, 연결하지 않기로 고른 달, 하위 작업, 에픽 | 없음 | 없음 |

Jira 이슈의 상위 항목은 하나뿐입니다.
그래서 다른 에픽에 있는 이슈를 옮기면 원래 에픽에서 빠지고, 이 영역은 직접 체크한 것만 옮깁니다.

- 묶음 머리의 체크박스로 그 달(또는 그 에픽)의 이슈를 한꺼번에 고르고, **Shift+클릭**으로 범위를 고릅니다.
  묶음 머리의 글자를 누르면 그 에픽이 Jira에서 열립니다
- 실행하면 확인창에 달별 건수와 넣을 에픽이 나옵니다.
  옮기기라면 빠지는 에픽도 함께 나옵니다
- **알림 메일**: 먼저 알림을 끄고(`notifyUsers=false`) 보내 봅니다.
  이 옵션은 Jira 관리자나 프로젝트 관리자만 쓸 수 있어서, 거절되면 알림을 켠 채로 보낼지 다시 묻습니다.
  켠 채로 보내면 이슈의 보고자와 지켜보는 사람에게 변경 알림이 갈 수 있습니다
- 보내기 직전에 이슈를 다시 읽어, 불러온 뒤 누군가 상위를 바꾼 이슈는 덮어쓰지 않고 건너뜁니다.
  보낸 뒤에도 다시 읽어서 실제로 바뀐 것만 성공으로 칩니다
- 실행이 끝나면 **결과창**에 이번에 넣은 건수가 에픽별로 정리돼 나옵니다.
  `[복사]`로 그대로 보고에 붙일 수 있습니다
- `[중지]`는 아직 보내지 않은 요청만 취소합니다.
  이미 바뀐 이슈는 그대로입니다

#### 변경 기록

에픽에 넣거나 옮긴 기록이 실행 묶음별로 쌓입니다.
직접 지우기 전까지는 기간 제한 없이 남습니다.

- **취소**는 그 이슈의 상위를 바꾸기 전으로 돌립니다.
  원래 상위가 없던 이슈는 상위를 떼고, 다른 에픽에 있던 이슈는 그 에픽으로 돌려놓습니다
- 취소 단위는 세 가지입니다.
  행의 `[취소]`(한 건), 에픽 묶음 머리의 `[N건 취소]`(그 에픽으로 들어간 것), 묶음 위쪽의 `[N건 모두 취소]`(그 실행 전체)입니다
- 검색으로 걸러 두면 에픽 단위와 묶음 단위 취소도 보이는 것에만 적용됩니다.
  예를 들어 원래 에픽 키로 걸러서 그 에픽에서 옮겨 온 것만 되돌릴 수 있습니다
- 그 사이 누군가 상위를 다시 바꾼 이슈는 건드리지 않고, 행에 사유를 남깁니다
- 취소도 보낸 뒤 이슈를 다시 읽어서, 실제로 상위가 바뀐 것만 `취소함`으로 적습니다.
  상위를 떼는 요청은 Jira 설정에 따라 성공을 돌려주고도 바뀌지 않는 형식이 있어서, 통할 때까지 형식을 바꿔 가며 보냅니다
- `[Jira 대조]`는 기록을 Jira의 지금 상태와 대조해서 고쳐 적습니다(Jira는 바꾸지 않습니다).
  `취소함`으로 적혔는데 아직 그 에픽에 붙어 있는 건은 적용 중으로 돌아와서 다시 취소할 수 있고, Jira에서 직접 상위를 바꾼 건에는 사유가 붙습니다
- 취소한 건도 기록에서 지우지 않고 `취소함 (시각)`으로 남깁니다.
  `[취소분 삭제]`로 치울 수 있고, `[전체 삭제]`는 적용 중인 변경의 기록까지 지웁니다.
  둘 다 이 목록만 지우고 Jira는 바꾸지 않습니다

Jira를 실제로 바꾸는 버튼은 `취소`로 끝나는 버튼(행의 `[취소]`, `[N건 취소]`, `[N건 모두 취소]`)뿐입니다.
`내역`이 들어간 버튼은 보고용 글을 띄우기만 하고, `삭제`가 들어간 버튼은 이 목록의 기록만 지웁니다.

`[추가 내역]`은 지금 적용 중인 변경을 에픽별 건수로 정리한 글을 띄웁니다.
여러 번 나눠 실행했거나 일부를 취소했어도 최종 상태로 셉니다.
묶음마다 있는 `[내역]`은 그 실행 하나만 셉니다.

```
* 1월 에픽: 19건 추가
* 2월 에픽: 22건 추가
합계 41건

다른 에픽에서 옮겨 온 이슈
* [팀] 26.03 CR에서 3건
```

`[취소 내역]`은 지금 취소된 상태인 변경을 에픽별 건수로 세고, 밑에 무엇을 취소했는지 이슈 목록을 붙입니다.
취소했다가 다시 넣은 이슈는 지금 넣은 상태라 빠집니다.
다른 에픽에서 옮겼다가 취소한 이슈는 돌아간 원래 상위를 옆에 적습니다.

```
* 4월 에픽: 2건 취소
합계 2건 취소

취소한 이슈
* 4월 에픽
  - ABC-101 기획 리뷰 참석
  - ABC-102 개발 공수 산정
```

> 확장을 고친 뒤 Jira 탭을 새로고침하지 않으면, 예전 스크립트가 상위 항목을 빼고 응답합니다.
> 그 상태로는 모든 이슈가 '상위 없음'으로 보여 이미 다른 에픽에 있는 이슈까지 옮길 수 있으므로, 이때는 불러오기를 멈추고 새로고침을 안내합니다.
> 연결, 옮기기, 취소는 탭에 심어 둔 스크립트를 거치지 않습니다.
> 실행할 때마다 최신 코드를 그 Jira 탭에 넣어 보내므로, 탭을 새로고침하지 않아도 늘 쓰기 전후 확인을 거칩니다.

### 단축키

- **mac**: `Cmd+Shift+X`
- **그 외**: `Ctrl+Shift+X`

충돌하면 `chrome://extensions/shortcuts` 에서 변경할 수 있습니다.

## 데이터와 네트워크

모든 데이터는 `chrome.storage.local` 에만 저장되고, **개발자 서버는 존재하지 않습니다.** 백업/복원도 로컬 JSON 파일 단위입니다.

네트워크 요청은 아래가 전부이며, 모두 사용자가 로그인해 둔 서비스의 공식 API입니다.

| 요청 | 용도 |
|---|---|
| `POST {jira}/rest/api/3/search/jql` | 이슈 검색 (읽기) |
| `GET {jira}/rest/api/3/search` | 위 실패 시 폴백 (읽기) |
| `GET {jira}/rest/api/3/issue/{key}?fields=parent` | 상위 변경 직전 확인과 변경 뒤 확인 (읽기) |
| **`PUT {jira}/rest/api/3/issue/{key}`** | **이슈의 상위 항목(에픽) 변경 (쓰기)** |
| **`POST {jira}/rest/agile/1.0/epic/none/issue`** | **상위 떼기가 PUT으로 안 될 때 쓰는 에픽 해제 (쓰기)** |
| `GET api.teamgantt.com/v1/groups`, `/projects`, `.../children` | 그룹·프로젝트·작업 조회 (읽기) |
| **`POST api.teamgantt.com/v1/tasks`** | **작업 생성 (쓰기)** |
| **`POST api.teamgantt.com/v1/tasks/resources/bulk/create`** | **담당자 할당 (쓰기)** |

TeamGantt 쓰기 요청 두 가지는 **`[선택 N건 등록]` 버튼에서만, 확인창을 통과한 뒤에** 실행됩니다.
Jira 쓰기 요청은 **에픽 탭의 연결, 옮기기 버튼과 변경 기록의 취소 버튼에서만, 확인창을 통과한 뒤에** 실행됩니다.
그 외에는 자동으로 실행되지 않습니다.

**삭제 요청은 없습니다.** 이 확장은 Jira와 TeamGantt의 데이터를 지우지 못합니다. `API 직통` 수집의 "정리" 기능은 로컬 사본만 정돈하는 것입니다.

동작 도메인은 `*.atlassian.net`, `app.teamgantt.com`, `api.teamgantt.com` 세 곳뿐입니다.
